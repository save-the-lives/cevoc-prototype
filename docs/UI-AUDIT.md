# UI audit: public page, phone and desktop

Report-only audit of the public CEVOC page (look-up form, notice page with four numbered steps, evidence viewer, certificate list, red light details, loading and error states) and the demo hub (`/demo-cases`). No application code was changed.

- Audited commit: `b09b263` (main). Date: 2026-11-06.
- Authority used: Digital NSW and the NSW Design System, whose pages state **WCAG 2.2 level AA** (see Sources). The underlying measure here is WCAG 2.2 AA; criteria that exist only in 2.2 are marked "(2.2)".
- Data: fictitious only (the demo cases served by the visual-check fixtures). No real notice numbers, plates or personal data appear in this document or in the screenshots.
- Test rig: production build served locally with the same mock API as `scripts/visual-check.mjs`, driven with Playwright and Chromium (phone 390x844 with touch emulation, desktop 1280x800), axe-core 4.14 (rules wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa and best-practice). The throw-away scripts lived outside the repository.

How to read the evidence column: **[auto]** = measured or reported by a script (axe, computed styles, layout-shift observer, DOM inspection). **[manual]** = my judgement from reading the code and screenshots. Nothing here was verified with a real screen reader (see "What could not be tested").

## 1. Summary: top 10 issues, ranked by user impact

1. **UI-01 "Edit" and the browser Back button empty the form.** Someone who mistyped one digit must retype the notice number and the date. WCAG 3.3.7 Redundant Entry (2.2, level A), and the NSW form guidance says not to make people re-enter data.
2. **UI-03 Expired photos look like a broken page.** A black box with a broken-image icon and almost invisible alt text (about 1.1:1), the same message and button three times, "Zoom in" still offered, and the heading line still says "Check the number plate and the vehicle in the photos". Photo links do expire, so this is a normal state, not a rare one.
3. **UI-02 Keyboard and screen reader focus is lost when the viewer opens.** Pressing "Zoom in" removes the button that has focus, and focus drops to the top of the page.
4. **UI-04 Browser autofill can put the person's birthday into the offence date.** The Day box is marked `autocomplete="bday-day"`.
5. **UI-06 The notice page jumps when the details arrive.** Layout shift 0.22 on the phone (0.06 on desktop; good is under 0.1) at the moment the person starts reading.
6. **UI-07 Screen readers are told too much.** Whole step bodies are polite live regions, so each arrival re-announces up to about 840 characters, and the live regions are nested.
7. **UI-10 Panning a zoomed photo needs a drag.** Zoom and photo changes have buttons, panning does not. WCAG 2.5.7 Dragging Movements (2.2, AA).
8. **UI-09 Header and footer are home-made, not the NSW Design System components.** No NSW Government logo or link, no copyright, accessibility or privacy links, no Acknowledgement of Country. The Design System marks Masthead, Header, Footer, Forms and Buttons as must-use for brand.
9. **UI-08 Most text sizes are fixed in pixels.** At a 200% browser text-size setting the headings doubled but the body text, buttons and links stayed at 17px.
10. **UI-11 The evidence images have thin text alternatives, and the video has no caption or description track.** The alt text repeats the visible title, and nothing says what the picture shows.

Counts: 3 High, 8 Medium, 12 Low (23 findings). Nothing failed the colour-contrast or reflow checks.

## 3. NSW Design System comparison

| Component | App status | Adopt or document |
|---|---|---|
| Masthead | Text bar "NSW Government", no logo, no link, no skip link inside it, outside any landmark | Adopt (required) |
| Header | `p.sitename` "Road safety enforcement" in a plain bar | Adopt, descriptor as site name |
| Footer | Phone number and "Prototype service" | Adopt (copyright required, add accessibility and privacy links, Acknowledgement of Country) |
| Button | Own `.btn` styles; navy primary and outline match the brand colours; disabled used while busy | Adopt DS classes, or document the variant mapping; replace `disabled` with `aria-disabled` |
| Link / link-style buttons | Actions styled as links ("Edit", "Try again") | Document: DS says use a button for actions, a link for navigation; keep one control (UI-15) |
| Form, Text input, hints, errors | Labels above fields, hints, `aria-describedby`, inline error plus summary; matches the guidance | Adopt DS markup for the error summary; document the privacy reason for the generic not-found message |
| Date input | Day, month, year fieldset with legend and hint like the DS, but auto-advances and uses `bday-day` | Adopt behaviour: no auto-advance, no birthday token (UI-04, UI-05) |

| Status labels | `.badge` "In force on the offence date" with a tick and text | Adopt, or document (colour is not the only cue, which is good) |

| In-page navigation | `nav "On this page"` list of anchors | Adopt (same pattern, left bar on desktop) |

## 4. Things done well

- Contrast: every text pair measured passes AA (lowest 5.08:1, white tick on green; body text 7:1 or better), and non-text borders measure 5:1 or better.
- Reflow, zoom and spacing: no horizontal scroll at 320 px, 200% or 400%; the text-spacing override clipped nothing. The page allows pinch zoom.
- Forms: visible labels, hints tied by `aria-describedby`, `aria-invalid`, error summary with links to fields, errors that say what to fix, numeric keypad, optional plate clearly marked, sensible `autocomplete="off"` on the notice number and plate.
- Focus: 3px visible ring everywhere checked, logical tab order, skip link works, focus moves to the new heading when the notice opens, page title changes per view.
- Touch: swipe, pinch and double-tap worked in emulation; the toolbar buttons are 44x44 or larger; the full-screen overlay is a real dialog with a focus loop, Escape, scroll lock and focus return.
- Motion: with reduced motion on, the skeleton, spinner and zoom animations are all off (no running animations found).
- Loading: the frame appears at once with labelled placeholders, so people see progress and the structure.
- Status is never colour alone (tick, dash, "Demo data" text, warning icon with "Error:" text).
- The notice number, date and plate stay out of the address bar and storage.
- Back works as expected from the notice page.

## 5. What could not be tested

- No real iPhone, Safari, VoiceOver, TalkBack, NVDA or JAWS. Live-region behaviour, reading order as spoken, and iOS Dynamic Type were not tested; only the DOM and the emulated phone were. Touch gestures were generated with Chrome DevTools events, not fingers.
- Native full screen was exercised in headless Chromium only (Escape handling by the browser could not be observed).
- Forced-colours and print screenshots were captured but not assessed in detail.
- Video playback with captions: the demo video has no caption file.
- Reading level of the wording was judged by eye, not scored. No user research was run.
- Design System pages that could not be read here (access refused by the fetch tool): the Steps, Media, Status labels, Progress indicator, List item and Close/Back to top detail beyond the Close button, and the Digital NSW Design Standards and Accessibility Testing pages. Comparisons for those components are marked as such and were not guessed.
